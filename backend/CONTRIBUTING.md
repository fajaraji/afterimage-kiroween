# Contributing

1. Read `AGENTS.md`, the active Kiro spec, and security constraints.
2. Prefer one PR per spec task with acceptance-test evidence.
3. Run `npm run validate:starter`, `npm run typecheck`, and `npm test` after installation.
4. Add or update tests for every changed business rule, especially deletion/replay semantics.
5. Use conventional commit messages (`feat:`, `fix:`, `test:`, `docs:`).
6. Never submit customer information, secrets, generated DB files, or raw production logs.
7. Disclose inherited or pre-existing code added to the project; comply with licenses.
