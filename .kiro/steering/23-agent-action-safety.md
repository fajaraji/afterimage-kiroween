# Consequential-action safety — v4 scope boundary

- P0 **remains data-resurrection regression testing** on isolated synthetic AWS resources; never pivot core delivery toward a production AI-agent firewall.
- P1 after P0: action intent → trusted policy decision → execution receipt → independent post-action observation; IDs and bounded timestamps link to existing run evidence. A receipt is not independent verification.
- P2 only after successful P0/Frankenstein integration: **synthetic-only denied action proposal**, with an allowlist and no actual arbitrary infrastructure deletion tool.
- Strands runtime investigator remains **read-only**, advisory, with no approval, execution, AWS management, secrets, or PASS/FAIL authority. Kiro development agents are separate.
- Authorization decisions are deterministic and server-side, default-deny, scoped to server-owned test run resources. Any exceptional approval must be human-authenticated, exact-payload-bound, expiring, one-time, and rechecked at execution.
- For denied proposals, independently query relevant stores before claiming no mutation. Failed queries mean `UNKNOWN`.
- Never let client text, model tools, logs, receipts, or screenshot animation serve as proof of execution outcomes.
- No secret-bearing logs, real customer data, unrestricted shell/SQL, IAM wildcard mutations, real production connectors, or unapproved spend.
