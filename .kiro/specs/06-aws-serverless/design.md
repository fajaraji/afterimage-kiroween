# Spec 06 — Design

## Targets and boundaries

`infra/` CDK v2 TypeScript (NEW); `apps/web` Vite/React to Amplify; `apps/api` Fastify DEV shell only; `apps/lambdas` for API/seed/deletion/release/SQS/verifier; `packages/contracts` and `packages/engine` framework neutral; `packages/aws-adapters` for DynamoDB/S3/SQS; `fixtures` remain synthetic.

## Data model

Primary and analytics replica have separate DynamoDB tables, PK `RUN#{runId}`, SK `SUBJECT#{subjectId}#GEN#{generation}`. Barrier table keyed similarly with deletion status and monotonic generation. Event idempotency table or per-run item keyed by `eventId`. `runs` holds ownership, workflow ARN/status, fixture hash, scenario ID/version, receipt status and result pointers. S3 objects prefixed by runId under controlled keys. All IDs and paths generated by backend, never supplied by arbitrary client input.

## Orchestration

Step Functions Standard: ValidateRun → SeedStores → CreateHeldEvent → ApplyDeletion/Fault → PublishStaleEventToSQS → PollReceiptWithTimeout → IndependentlyVerify → PersistEvidence → Complete. The hold is implemented in explicit scenario metadata; SQS event is published after deletion to deterministically simulate delayed arrival. SQS/Lambda delivers at least once. Verification after bounded receipt wait, otherwise UNKNOWN.

The unsafe mode is demonstrative on synthetic-only partitions. Protected replica write and barrier ConditionCheck MUST be performed atomically in DynamoDB transaction or equivalent condition on same aggregate; protect against TOCTOU races. Run metadata and barrier are server owned, not writable by frontend.

## Evidence

Normal form of observation includes store ID, scope, run ID, subject generation, `PRESENT|ABSENT|UNKNOWN`, AWS operation identifier when safe, checkedAt and evidence ID. Frontend only visualizes persisted result. Logs contain only synthetic IDs and redacted traces.

## Deployment and testing

Unit tests use in-memory adapters; integration tests query real sandbox AWS services; E2E tests exercise Amplify/API URLs. Use CloudWatch Powertools for structured logs and metrics. S3 exports versioned only in P1 with accurate version verification. No multi-region/global tables in P0. CDK synth/diff, least privilege review, cost/quota caps and manual deployment approval required.
